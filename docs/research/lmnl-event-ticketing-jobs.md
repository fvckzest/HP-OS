# LMNL event and ticketing jobs inventory

Research for [Inventory LMNL event and ticketing jobs](https://github.com/fvckzest/HP-OS/issues/2), 2026-09-26.

## Evidence boundary

The source inventory below uses LMNL `main` at [`1bffe4a`](https://github.com/fvckzest/LMNL/tree/1bffe4a89109f9fe897509894253ab5c00bfff67), verified against `origin/main` on 2026-09-26. The linked open LMNL issues provide reported production evidence and planned fixes. Code proves that an action is implemented; it does not prove that staff use it, that every deployed environment is configured, or that a buyer completed the journey. No staff interview, production database inspection, payment test, or visual review was performed. The older LMNL pilot audit and specifications were not treated as current HP-OS decisions.

## Controls that appear broken, mixed, or candidates for removal

These are findings for later decisions, not instructions to delete controls.

1. **Public checkout appears in the private invite queue.** The public checkout adapter persists an approved `Access Request` with a placeholder name/email when the buyer has not supplied them, while the Admin table lists `requests` as Invite Requests. [Adapter](https://github.com/fvckzest/LMNL/blob/1bffe4a89109f9fe897509894253ab5c00bfff67/api/_lib/adapters/ticketing-checkout.js#L93-L111), [Admin table](https://github.com/fvckzest/LMNL/blob/1bffe4a89109f9fe897509894253ab5c00bfff67/src/components/admin/EventsTab.jsx#L953-L1024). [LMNL's open issue](https://github.com/fvckzest/LMNL/issues/42) reports a production example in which the Square order was still a draft and no ticket existed. This is evidence of a mixed workflow and misleading count/status, not evidence that private approvals are unnecessary.
2. **A real public buyer can remain `Guest`.** [LMNL's open issue](https://github.com/fvckzest/LMNL/issues/43) reports a production purchase whose Square customer/payment held a name while LMNL retained `Guest`; the issue traces this to using recovered email as a proxy for whether Square may repair the name. This makes holder and door records less reliable. The report contains buyer details, so this inventory does not repeat them.
3. **One checkout currently leads to one visible ticket.** The public page sends no quantity, so the core defaults it to one; confirmation links to a single `/ticket/:id`. [Page action](https://github.com/fvckzest/LMNL/blob/1bffe4a89109f9fe897509894253ab5c00bfff67/src/pages/EventPage.jsx#L89-L100), [checkout wrapper](https://github.com/fvckzest/LMNL/blob/1bffe4a89109f9fe897509894253ab5c00bfff67/api/_lib/services/checkout.js#L399-L410), [core quantity input](https://github.com/fvckzest/LMNL/blob/1bffe4a89109f9fe897509894253ab5c00bfff67/packages/ticketing-core/src/index.js#L119-L145), [confirmation link](https://github.com/fvckzest/LMNL/blob/1bffe4a89109f9fe897509894253ab5c00bfff67/src/pages/Success.jsx#L138-L146). [LMNL's open issue](https://github.com/fvckzest/LMNL/issues/41) specifies group purchase and an order-level retrieval page. The generic core's quantity parameter is foundation, not proof of a complete buyer journey.
4. **Event status and presentation settings are spread across controls.** The Admin status selector offers `active`, `past`, `sold_out`, `draft`, and `archived`, while the public page service also reads other status strings plus metadata publication/sales flags; event links may point to an explicit metadata link, Partiful, a generated page, or `/space` fallback. [Admin statuses](https://github.com/fvckzest/LMNL/blob/1bffe4a89109f9fe897509894253ab5c00bfff67/src/components/admin/EventsTab.jsx#L1154-L1163), [public status/availability](https://github.com/fvckzest/LMNL/blob/1bffe4a89109f9fe897509894253ab5c00bfff67/api/_lib/services/public-event-page.js#L64-L73), [link precedence](https://github.com/fvckzest/LMNL/blob/1bffe4a89109f9fe897509894253ab5c00bfff67/src/lib/eventLinks.js#L47-L59). The relationship among publication, sales, and event lifecycle needs clarification; it is not yet evidence that any one control should be removed.
5. **Site-only or diagnostic controls need an owner.** The Admin form exposes Home/Featured flags, Partiful and manual event-page links, arbitrary custom traits, and a `CREATE TEST ITEM` action that creates a real Square catalog item after confirmation. [Flags](https://github.com/fvckzest/LMNL/blob/1bffe4a89109f9fe897509894253ab5c00bfff67/src/components/admin/EventsTab.jsx#L798-L815), [links and traits](https://github.com/fvckzest/LMNL/blob/1bffe4a89109f9fe897509894253ab5c00bfff67/src/components/admin/EventsTab.jsx#L1248-L1287), [test-item action](https://github.com/fvckzest/LMNL/blob/1bffe4a89109f9fe897509894253ab5c00bfff67/src/components/admin/EventsTab.jsx#L332-L348). These may be useful LMNL presentation/debug controls but do not yet show an HP-OS operational job. Ask staff which are used before copying or removing them.
